* Dotfiles Management with GNU Stow
This repository contains my personal configuration files (dotfiles).
They are organized so that I can easily manage them across multiple machines using [[https://www.gnu.org/software/stow/][GNU Stow]].

Everything here runs on both macOS and Linux. The shell, tmux and Claude Code
packages branch on ~uname~ where they have to; the packages that genuinely do not
apply to a platform are called out under [[*Per-platform notes][Per-platform notes]].

** Clone this repository into your home directory (or wherever you prefer):
#+begin_src bash
git clone git@github.com:Exotica0122/dotfiles.git ~/github.com/Exotica0122/dotfiles
cd ~/github.com/Exotica0122/dotfiles
#+end_src

** Install GNU Stow (if not already installed):
- macOS (Homebrew): ~brew install stow~
- Arch: ~sudo pacman -S stow~
- Linux (Debian/Ubuntu): ~sudo apt install stow~
- Linux (Fedora): ~sudo dnf install stow~

** Usage
To symlink a config, run stow from inside the repo:

*** Symlink configs:
#+begin_src bash
find . -mindepth 1 -maxdepth 1 -type d ! -name ".git" -exec basename {} \; | xargs stow -Rv --no-folding --target=$HOME
#+end_src

This will create symlinks in your home directory that point to the files in this repository.

Stow refuses a package outright when any one of its files already exists as a real
file, and links nothing. Keep the local copy and link the rest with ~--ignore~:

#+begin_src bash
stow -Rv --no-folding --ignore='\.p10k\.zsh' --target=$HOME zsh
#+end_src

*** Packages
**** macOS — Homebrew
Pre-requisite: install [[https://brew.sh/][brew]].
#+begin_src bash
brew bundle --file=Brewfile
#+end_src

**** Arch — pacman + AUR
~Pkgfile.arch~ is the same list in pacman terms, ~pkg~ for the official repos and
~aur~ for the rest. It carries notes on the handful of Brewfile entries that have
no Linux counterpart.
#+begin_src bash
sudo pacman -S --needed $(sed -n 's/^pkg "\(.*\)"$/\1/p' Pkgfile.arch)
yay        -S --needed $(sed -n 's/^aur "\(.*\)"$/\1/p' Pkgfile.arch)
#+end_src

*** Plugins
Neither plugin manager installs itself, and *neither installs anything until you tell
it to* — stowing the configs is not enough. Until this runs, ~ctrl+h/j/k/l~ does not
move between panes, because that binding comes from ~vim-tmux-navigator~ on both sides.

tmux, via TPM:
#+begin_src bash
git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm
~/.tmux/plugins/tpm/bin/install_plugins     # or prefix + I inside tmux
tmux source-file ~/.tmux.conf               # pick up the new bindings now
#+end_src

Neovim, via lazy.nvim — it installs on first launch, but only for the specs it can
see, so run it again after adding one:
#+begin_src bash
nvim --headless "+Lazy! install" +qa        # or +Lazy! restore to match lazy-lock.json
#+end_src

Check both sides agree:
#+begin_src bash
ls ~/.tmux/plugins                          # expect 6, tpm included
tmux list-keys -T root | grep -c '^bind-key -T root C-[hjkl] '   # expect 4
#+end_src

* Per-platform notes

** ghostty
The config lives at the XDG path, ~ghostty/.config/ghostty/config~, which Ghostty
reads on macOS as well as Linux.

Do *not* stow this package on an [[https://omarchy.org/][Omarchy]] machine: Omarchy ships its own
~~/.config/ghostty/config~ wired to the live theme, and this one would replace it.

** hypr, waybar, swayosd — Omarchy only
These three packages only apply to an [[https://omarchy.org/][Omarchy]] machine. Do *not* stow them on macOS,
and expect Omarchy to own the paths alongside them.

Only the hand-authored files are tracked. ~autostart.conf~, ~hyprsunset.conf~ and
~xdph.conf~ are byte-identical to Omarchy's defaults, so they are left for Omarchy
to create; ~walker/config.toml~ and ~fontconfig/fonts.conf~ likewise.
~mako/config~ is deliberately absent — it is a symlink into
~~/.config/omarchy/current/theme/~ and must stay one.

Omarchy creates every one of these files on install, and stow refuses a package
when a target already exists, so remove the local copy before the first stow on a
new machine:
#+begin_src bash
rm ~/.config/hypr/{bindings,envs,hypridle,hyprland,hyprlock,input,looknfeel,monitors}.conf
rm ~/.config/waybar/{config.jsonc,style.css} ~/.config/swayosd/{config.toml,style.css}
stow -Rv --no-folding --target=$HOME hypr waybar swayosd
#+end_src

Two things write *through* the symlinks, straight into this repo — which is mostly
what you want, since the change then shows up in ~git diff~:
- ~omarchy refresh <app>~ and update migrations ~cp~ their defaults over these paths.
  A migration will happily reset ~hypridle.conf~ timeouts this way.
- ~omarchy theme set~ rewrites the theme files it owns, which these only ~@import~.

One thing *breaks* the symlinks: ~omarchy font set~ runs plain ~sed -i~ (no
~--follow-symlinks~) against ~hyprlock.conf~, ~waybar/style.css~ and
~swayosd/style.css~, which replaces each symlink with a regular file and leaves the
repo copy on the old font. Re-stow after changing the font:
#+begin_src bash
omarchy font set "CaskaydiaMono Nerd Font"
stow -Rv --no-folding --target=$HOME hypr waybar swayosd   # re-link what sed detached
#+end_src

~hypr/.config/hypr/envs.conf~ is the machine-specific file here: it carries the
NVIDIA variables for a Turing+ card (an RTX 3060), and Omarchy's installer appends
its own per-GPU block to that path. On a machine with different graphics, let
Omarchy write it and skip ours (see ~--ignore~ above). Note also that nothing in
Omarchy sources this file on its own — ~hyprland.conf~ has an explicit
~source = ~/.config/hypr/envs.conf~ line for it.

The desktop stack itself — hyprland, waybar, walker, mako, swayosd — is absent from
~Pkgfile.arch~ on purpose: Omarchy's own base install provides it.

** tmux
~tmux-status~ reads load, memory and battery from ~sysctl~/~pmset~ on macOS and
from ~/proc~ and ~/sys/class/power_supply~ on Linux. A machine with no system
battery drops the battery segment rather than printing a permanent ~??~; a
peripheral battery (a wireless mouse reports as a power supply too) is ignored
via ~scope=Device~.

The ~prefix + u~ URL picker opens through ~open-url~, which is ~xdg-open~ on Linux
and ~open~ on macOS.

** zsh
~.zshenv~ and ~.zshrc~ branch on ~uname~ for Homebrew vs pacman paths, fnm and pnpm
data directories, and the Homebrew-vs-~/usr/share~ locations of the zsh plugins.
~caffeinate~ wrapping of ~claude~ is macOS-only.

~.p10k.zsh~ is tracked but is the most machine-specific file here: it bakes in the
font, the colour scheme and whether the terminal can draw box glyphs. Expect to
keep a local copy per machine (see ~--ignore~ above) rather than sharing one.

** claude
~claude/.claude/statusline.sh~ is portable. The rest of the Claude Code setup —
settings, hooks, skills, memory — lives in the private ~dotfile-agents~ repo, and
the session HUD it points at lives in [[https://github.com/Exotica0122/fromis_9-hud][fromis_9-hud]].
